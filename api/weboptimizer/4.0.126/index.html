Project Status

Use case

One development tool for web and Node.js projects instead of a hand-written webpack, Babel, TypeScript, Jest, ESLint and PostCSS setup. weboptimizer brings working defaults for all of them: it builds libraries and web applications from TypeScript, JavaScript, CSS and EJS templates, runs a development server, tests, type checks, linting and documentation. Everything you want to change is configured in your "package.json".

Content

Quick start

A TypeScript library with tests:

npm install --save-dev weboptimizer core-js jest @types/webpack-env

{
  "name": "greeter",
  "type": "module",
  "main": "dist/index.js",
  "files": ["dist"],
  "scripts": {
    "build": "weboptimizer build",
    "check:types": "weboptimizer check:types",
    "clear": "weboptimizer clear",
    "test": "weboptimizer test",
    "watch": "weboptimizer build --watch"
  },
  "webOptimizer": {
    "path": {
      "source": {"base": "src/"},
      "target": {"base": "dist/"}
    }
  }
}

// src/index.ts
export const greet = (name: string): string => `Hello ${name}!`

export default greet

// src/test.ts
import {expect, test} from '@jest/globals'

import greet from './index'

test('greet', (): void => {
    expect(greet('World')).toStrictEqual('Hello World!')
})

"npm run build" writes "dist/index.js", "npm test" builds the tests and runs them with Jest.

Libraries and applications

weboptimizer distinguishes two kinds of projects. Many defaults depend on it:

  • Library (default): Every source file is compiled on its own, imported packages stay external. Without a "path" configuration the output is placed next to the sources, therefore the quick start sets "src/" and "dist/".
  • Application ("library": false): Everything including dependencies is bundled from "src/" into "dist/" together with an "index.html". Stylesheets belong into "src/cascadingStyleSheet/", images into "src/image/" and fonts into "src/font/". An own "src/index.html.ejs" replaces the default page.
{
  "scripts": {
    "build": "weboptimizer build",
    "serve": "weboptimizer serve"
  },
  "webOptimizer": {
    "library": false
  }
}

Commands

  • "build": Builds the project. Further arguments go to webpack, e.g. "weboptimizer build --watch" rebuilds on every change.
  • "serve": Starts a development server on port 8080 which reloads the page on changes.
  • "test": Builds all files named "test" and runs them with Jest in Node.js. For a simulated browser set "commandLine.test.environments" to ["jsdom"]. "test:coverage" adds a coverage report.
  • "test:browser": Serves the tests to run them in a real browser.
  • "check:types" and "build:types": Checks the TypeScript types or writes declaration files.
  • "lint": Checks scripts with ESLint and stylesheets with Stylelint.
  • "document": Generates API documentation with JSDoc.
  • "clear": Removes all build output.

Optional features

Features beyond building scripts need additional packages:

  • Stylesheets: "css-loader", "style-loader", "mini-css-extract-plugin", "postcss-loader", "postcss-import", "postcss-preset-env", "postcss-url", "postcss-fontpath" and "cssnano".
  • Development server: "webpack-dev-server".
  • Linting: "eslint", "@eslint/js", "eslint-config-google", "eslint-plugin-jsdoc", "typescript-eslint", "@stylistic/eslint-plugin" and "globals", for stylesheets "stylelint" and "stylelint-config-standard".
  • Favicons from "src/image/favicon.png": "favicons-webpack-plugin".
  • Image compression: "imagemin" plus "imagemin-gifsicle", "imagemin-jpegtran", "imagemin-optipng" and "imagemin-svgo" (disabled by default, enable it by setting "module.optimizer.image.content.exclude" to "null").
  • Offline support via service worker: "workbox-webpack-plugin".
  • API documentation: "jsdoc".

Configuration

All settings live under the key "webOptimizer" in your "package.json" and are merged into the defaults, which you find under "configuration" in weboptimizer's own "package.json". Keys like "#" or "#1" are comments:

{
  "webOptimizer": {
    "#": "Serve on another port.",
    "development": {
      "server": {"port": 9000}
    },
    "generic": {
      "supportedBrowsers": ["last 2 versions", "> 1%"]
    }
  }
}

The sections "debug", "document", "test" and "test:browser" are merged in only for the corresponding command or for debug mode. Debug mode leaves stylesheets and HTML unminified and is enabled via "debug": true (also on the command line) or the environment variable "NODE_ENV=development".

Computed values

Values can be JavaScript expressions with "evaluate" or function bodies with "execute". "self" is the whole configuration, further available are e.g. "currentPath", "path", "fs", "webOptimizerPath" and the helpers of clientnode like "string" or "array". Computed locations in "path" are made absolute like plain ones:

{
  "webOptimizer": {
    "libraryName": {"__evaluate__": "`${self.name}-library`"},
    "path": {
      "target": {
        "base": {"__evaluate__": "self.debug ? 'build/' : 'dist/'"}
      }
    }
  }
}

Command line

The last argument of a command can be a JavaScript object which overrides the configuration. "reference" merges in named sections of your configuration (or JSON files), which is handy for build variants:

{
  "scripts": {
    "build:bundle": "weboptimizer build '{__reference__: \"target:bundle\"}'"
  },
  "webOptimizer": {
    "target:bundle": {
      "inPlace": {"externalLibrary": {"normal": true}},
      "path": {"target": {"base": "dist/bundle/"}}
    }
  }
}

npx weboptimizer serve '{development: {server: {port: 9000}}}'

If your toolchain can not pass such characters, encode the object as base64:

npx weboptimizer build \
    "$(printf '%s' "{path: {target: {base: 'out/'}}}" | base64)"

Editor integration

Point your editor's ESLint integration to the project's "eslint" package and to the configuration "node_modules/weboptimizer/dist/eslint.config.js". TypeScript configurations can extend "weboptimizer/tsconfig.json".
